# Evaluation

Everything below is **measured by executing the real pipeline** against
constructed ground truth. Nothing is simulated except the two retrieval
baselines, which are genuine alternative implementations.

## Datasets (generated, `scripts/generate_benchmark.py`)
* `data/evaluation/pairs/pair_NNN/` — 32 rendered revision pairs with
  `manifest_a.json`, `manifest_b.json`, `ground_truth.json` (changed semantic,
  type, old/new values, bbox, affected component, expected impact class).
  Ground truth is produced *by construction* (parameterised perturbation), so
  detection can be scored exactly.
* `retrieval_qrels.json` — 12 queries with relevant requirement codes or
  `Document§section` keys.
* `tool_cases.json` — 14 messages with expected tool sets.

## Metrics
* change detection: precision / recall / F1, type accuracy, localization
  confirmation rate (CV region overlaps ground-truth bbox), extraction exact &
  normalized accuracy;
* retrieval: Recall@5, MRR, nDCG@5 per strategy + mean latency;
* agent: tool-selection accuracy;
* grounding: findings-with-evidence rate, unsupported-claim rate (every
  reported old/new value must exist in the source manifests), insight grounded;
* system: analysis latency, retrieval latency, tool latency.

## Honest caveats
* The change-detection benchmark validates the *pipeline* (manifest diff +
  OpenCV confirmation + extraction) against ground truth generated by the same
  diff function; precision/recall of 1.0 therefore measure plumbing and CV
  agreement, not an independently trained detector. The CV stage is the
  independent signal: `localization_confirmation_rate` reports how often
  OpenCV sees the same regions without being told.
* Retrieval numbers use the offline hashing embedder unless a real embedding
  endpoint is configured; expect different (typically better semantic) results
  with a real model. The *relative* ordering of strategies on metadata-heavy
  queries is the durable result.

## Running
```
make eval            # or POST /evaluation/run
GET /evaluation/runs # persisted runs + metrics + report path
```
Reports land in `data/reports/evaluation_<run>.json`.
